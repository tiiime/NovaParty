# 跳绳 0.1.1

参考 Jump Rope Challenge 的轻量运动形式，使用原创矢量小动物和场景。内置 `jump_rope` Mod，需要基础客户端 0.1.9。封面使用 SVG 原文（`cover.svg.txt`），避免引擎导入删除源文件而导致跨设备指纹不同。普通包和热更新包分别由 `tools/pack_mod.py` 和 `--hot` 生成。

## 使用

大屏启动「跳绳」，选择「大屏展示」。手机在同一局域网加入此游戏后，选择「作为控制器加入」。设备角色由用户选择，不根据电视/手机型号强制分配；无加速度传感器时控制器按钮不可用，但仍可作为展示端。0.1.11 起可自动搜索、扫码或手动地址加入；缺少 Mod 时通过确认下载继续。

大屏持续等待，不设开始倒计时或结束人数门槛。控制器随时加入、离开或切换角色，其他控制器继续运动。一个人居中，两人平分场景，三至四人用两列网格；每人独立累计次数。最多五台设备、四个运动控制器，通常为一台大屏加四部手机。昵称沿用平台身份。

手机拿稳约 1.2 秒完成校准，之后用加速度模长偏离基线的峰值计数。首次加入、重新校准、角色变更、失联/恢复、切后台及打开/关闭平台弹窗均会重新校准。手机立即播放反馈，随后通过局域网同步大屏。重新选择角色或断线离开会清空该控制器本次计数；第一版没有历史记录、目标任务或真实动作准确率保证。

## 动作识别

`motion.gd` 是独立、可输入样本测试的检测器：

- 默认触发偏差 `2.6 m/s²`，回落到 `1.0 m/s²` 内重新允许触发。
- 默认冷却 350 ms，持续高峰不会重复计数。
- 校准至少 30 个有效样本，方差过大时重做；无效/零向量不算传感器存在。
- 不依赖手机朝向；这是运动峰值计数，挥动和其他运动也可能计数，后续依据实测调参。
- 原始传感器数据留在本机，只发送带角色代次的累计次数。

安卓需要基础包启用 `input_devices/sensors/enable_accelerometer`；iOS 同样使用 Godot 的 Input 接口。模拟器缺乏真实加速度输入时不能假装可用。修改算法、阈值、资源和 UI 可热更新；SDK 和引擎传感器开关需要基础包更新。

## 联机规则

清单声明 `session_mode: "drop_in"`、`players: {min: 1, max: 5}`。SDK 为此模式放宽全员到齐门槛，并允许已知历史 revision 的请求按当前状态重新验证。该行为不作用于棋牌 Mod。规则的 `presence_changed` 在加入/离线时重置槽位并递增 `generation`。

所有动作携带当前 `generation`，避免离开前的旧动作影响新加入的人。`role` 选择展示、控制器或未选择；`jump` 携带单调递增的绝对 `count`。重复提交不重复加分，并发控制器不因共享 revision 竞争丢计数。每次最多推进 16 次，客户端会补发尚未确认的计数。Drop-in 回执缓存限 512 项；离线槽位可复用，更换身份时清理旧回执。棋牌仍保留原有严格版本与恢复凭据机制。

TCP 关闭即移除小动物；网络静默失联沿用 SDK 心跳超时检测，最长约 8 秒。展示端为连接发起设备时，其退出会结束整个会话；首版不做主机迁移。

## 验证

- `Godot --headless --path . --script tests/jump_rope.gd`：动态人数、并发计数、去重、无效数据、代次隔离、空位复用、棋牌行为不变、传感器校准/阈值/冷却、布局和减少动态效果。
- `python3 tests/jump_rope_network.py`：三个真实 Godot 客户端通过 TCP 验证等待、双控制器并发计数、离开/再加入、位置复用、角色切换、无人后继续等待，以及活动会话中的 Mod 表现热更新。
- `Godot --path . --script tests/capture_jump_rope.gd`：真实渲染的等待、单人、双人、四人、手机及英文截图；人数与次数为测试数据，不作为硬件动作识别证据。
- `tests/jump_rope_devices.py`：安卓真机传感器、实际 adb 角色触屏与校准，以及 iOS 模拟器展示端的加入/离开。物理跳跃识别需真人另测，不能用 Debug 提交代替。

电视普通 adb 安装 0.1.9 被系统校验拒绝，未修改安全设置；APK 已放电视 `Download/novaparty-0.1.9-debug.apk`。手动更新基础包后才能加载此 Mod，旧基础包不能仅靠 UI 热更新获得动态人数和传感器配置。

本次验证结果：专项 40 项、0 失败；三客户端 TCP 和活动 Mod 热更新通过；Mi 11 实际加速度计、触屏选择控制器、静止校准通过，测得基线约 9.76 m/s²；iOS 模拟器作为展示端验证加入/离开通过。设备报告为 `build/validation/jump-rope-devices.json`。尚未进行真人持手机跳跃的识别准确率测试，电视后续已更新至 0.1.12，但跳跃准确率和电视最新画面/听感仍需实测。
