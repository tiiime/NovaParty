# Debug 网络接口与热更新设计草案

状态：2026-11-01，D1 / D2 已实现，使用方式与实际边界见 [网络 Debug](debug.md) 和 [热更新](hot-updates.md)。0.1.3 已完成本机双进程及 Android 手机真机热更新验证；TCL 电视安装后也已通过真机验证。D3 仍为规划。本文保留总体设计，实际已交付契约以 debug.md 为准。

## 1. 目标

让开发工具和 AI 通过网络直接观察、操作和更新 Debug 客户端，减少 adb、截图识别、重新安装 APK 的频率。

第一阶段必须支持当前的真实对局：AI 连接电视，获取本机玩家可见的结构化棋盘、轮次与合法操作，订阅变化，以本机玩家身份提交落子，收到可关联的接受或拒绝结果。手机玩家保持正常操作。

Debug 接口独立于对局连接，不占玩家座位，不要求中心服务器，也不读取手机或其他设备的数据。

## 2. 启用与连接

建议默认使用 TCP + 换行 JSON-RPC 2.0，默认端口 27841。复用现有 Wire 的分帧机制，不共用对局端口 27840、握手凭据或消息分发器。提供 Python `nvctl` 工具输出 JSON，供人和 AI 调用；后续如需浏览器面板，再添加 WebSocket 适配。

连接流程：

1. Debug 包启动后，在开发面板显示选定的本地监听地址、端口与连接状态。
2. 生成独立的高熵开发令牌。首次通过设备界面或 adb 获取连接配置，CLI 从本地配置文件读取，避免反复手输。
3. 工具连接并认证，协商 Debug 协议版本及能力。
4. 选择 `play` 或 `inspect` 会话。默认 `play`，随后订阅需要的主题。
5. 应用重启、关闭开发服务或撤销配对时，使旧令牌及开发会话失效。

网络监听绑定选定的本地网卡地址，地址变化后重新绑定并显示新地址。认证前仅允许认证消息，限制连接数、认证次数和超时。令牌不进入公开广播、对局快照、诊断导出或普通日志。

首轮用于受控开发局域网；令牌认证不等同于加密。接口结构应允许后续添加 TLS 或通过开发机隧道连接。

## 3. Debug 与 Release 边界

同时要求引擎 Debug 构建标记与专用 `novaparty_debug` feature，防止仅凭运行时设置开启。

- 拆分明确的 Debug / Release 导出预设。
- Release 导出排除 Debug 服务脚本、开发面板、上传和重载入口。
- 宿主通过条件动态加载 Debug 服务，不通过全局 preload 强制引入。
- Release 不支持通过 Mod、命令行或配置切换为开发服务。
- 验收检查 Release 产物文件、运行时监听端口和相关入口，而不只检查一个布尔开关。

当前只有一个 Android 导出预设，需要在实现阶段完成拆分；本文不将现有构建过程当作已经具备 Release 隔离。

## 4. 能力分组

| 分组 | 首轮接口 | 说明 |
| --- | --- | --- |
| 设备 | `device.info`、`debug.capabilities` | 应用/SDK/协议版本、平台、构建、显示与输入能力 |
| 房间 | `room.status` | 是否连接、房主/参与者、本机座位、玩家列表和当前 Mod；不暴露恢复凭据 |
| 游戏 | `game.snapshot`、`game.describe_actions` | 本机可见状态、规则版本、操作描述、可执行操作或其查询方式 |
| 操作 | `game.submit` | 以本机座位提交正常操作，携带预期版本及请求 ID |
| 订阅 | `events.subscribe`、`events.unsubscribe` | 快照、连接、操作结果、错误和重载事件 |
| 界面 | `ui.describe`、`ui.input`、`ui.capture` | 可选：有稳定 ID 的控件、焦点和语义输入；截图作为界面验证补充 |
| 诊断 | `logs.tail`、`metrics.get` | 有界日志、帧耗时、连接与队列指标，输出脱敏 |
| 包管理 | `packages.list`、上传、校验、激活、回滚 | 后续阶段提供，不与任意文件写入混合 |

`play` 会话只获得本机玩家的可见信息和正常操作能力。房主内部状态、随机数状态及全部手牌不进入该模式。

`inspect` 是开发面板明确开启的额外权限，可在房主设备上调试完整规则状态。正常对局助手使用 `play`；不能因为连接的是房主设备，就默认获得全部手牌。

不提供任意 shell、任意文件访问或通用 eval。游戏包上传通过专门的可信代码开发通道完成。

## 5. 状态与操作契约

订阅响应首先给出完整快照，随后发送带递增 `event_seq` 的事件。事件序号覆盖连接和界面变化，不能用对局 revision 替代。断线后可从有限事件缓冲恢复；超出范围返回 `resync_required` 并重新获取完整快照。

每份游戏状态包含：

- `app_instance_id`：本次应用运行，重启后变化。
- `game_session_id`：本次对局，重开后变化。
- `state_epoch`：规则运行代次，规则切换后变化。
- `revision`：当前权威对局版本。
- `seat`、连接状态和 Mod 指纹。
- `view`：严格复用 `rules.view_for` 的本机可见结果。

当前游戏协议没有完整的 session/epoch 字段；第一阶段可由宿主包装会话标识，规则热更新阶段需要升级对局协议，使它们真正参与权威校验。

示意请求：

```json
{"jsonrpc":"2.0","id":"read-1","method":"game.snapshot","params":{}}
```

示意事件：

```json
{
  "jsonrpc":"2.0",
  "method":"events.snapshot",
  "params":{
    "event_seq":18,
    "game_session_id":"match-a",
    "state_epoch":0,
    "revision":5,
    "seat":1,
    "view":{"board":[],"turn":1,"finished":false}
  }
}
```

示意操作：

```json
{
  "jsonrpc":"2.0",
  "id":"rpc-7",
  "method":"game.submit",
  "params":{
    "request_id":"controller-a:move-3",
    "game_session_id":"match-a",
    "state_epoch":0,
    "expected_revision":5,
    "action":{"type":"place","x":6,"y":8}
  }
}
```

坐标为从 0 开始的逻辑坐标，避免依赖屏幕尺寸。工具不得自报其他座位。操作仍经 Session → 房主 → Mod 校验，不能直接修改棋盘。

RPC 的 `id` 用于关联网络调用，`request_id` 用于动作幂等。重试同一动作必须保留其 ID 与有效载荷；新状态下重试修改后的动作必须使用新 ID。RPC 先返回入队状态，最终结果通过 `action_result` 事件或结果查询获取，不能把“已发出”当作“已落子”。

当前 `Session.submit` 自动生成请求 ID 且不向调用方暴露成功收据，需补充可传入请求 ID/预期版本的接口、结果信号和有界结果查询。UI、Debug 工具和将来的 AI 玩家共用这条动作路径。

## 6. Mod 的 AI 接口

规则除了现有 `initial_state / apply / view_for`，补充可选的操作描述契约：

- JSON Schema 或等价结构：操作名、字段、类型、范围及解释。
- 基于本玩家可见状态的合法操作查询。
- 游戏阶段、当前可行动玩家、终局和结果的通用元信息。

五子棋可以返回合法空位；麻将、扑克需要按响应窗口返回玩家当前可用操作。大量操作可分页或用参数约束表达。合法操作查询本身也要遵守私有信息边界，不得泄露对手手牌或暗牌。

AI Skill 说明如何连接、订阅、识别自己回合、提交动作、等待最终收据与处理重同步；游戏专属 Skill 解释玩法，不要求 AI 识别像素。

## 7. 热更新分层

| 更新对象 | 目标行为 | 范围 |
| --- | --- | --- |
| 表现和资源 | 保留对局，重建本机界面，再渲染最新可见快照 | 优先实现；首批覆盖 GDScript 表现与原始资源 |
| 游戏规则 | 暂停接收动作，协调所有参与设备更新，再迁移状态或重开 | 后续实现，不能单端直接替换 |
| 宿主框架/原生代码 | 通过新 APK 更新并重启 | 不作为首轮 Mod 热更新目标 |

需要导入的纹理、音频、场景资源，应另做跨设备构建和加载验证。上传完成并不代表任意 Godot 资源已经具备跨平台兼容性。

### 7.1 传输与暂存

使用 `upload.begin / chunk / finish`：声明大小、内容 SHA-256 和类型，服务端分配上传 ID；分块传输并确认序号，完成后校验整体内容。建议原始分块 24 KiB，经过 base64 后仍小于当前 64 KiB 消息上限。

限制总体大小、同时上传数、暂存空间和超时；重复分块必须匹配原内容。断开只留下可清理的暂存文件，不自动激活。包只能进入应用私有开发目录，客户端不能指定任意目标路径。

### 7.2 版本并存与缓存

当前 ModLoader 使用固定 `res://mods/<id>/`，拒绝同名包，不能直接作为热更新加载器。

建议新开发包使用独立命名空间：

```text
res://mod_versions/<mod_id>/<build_id>/...
```

`build_id` 在打包前生成且不可变，独立于最终内容哈希，避免把最终哈希写进包路径造成自引用。逻辑游戏 ID、构建 ID、内容指纹分别记录。打包器校验资源引用指向正确代次，禁止跨代次或跨 Mod 的隐式依赖；新入口不使用全局 class_name 注册。

首次采用原始脚本和明确依赖路径。带 UID 与导入产物的场景包需要后续单独验证，不能靠字符串替换保证兼容。

挂载新命名空间并创建新实例，保留旧实例供可检测失败时回退。资源缓存替换选项不等同于完整应用状态迁移；不把重载已有 Script 对象当作规则热更新基础。

资源包没有作为本方案依赖的运行时卸载流程。释放旧节点不代表所有挂载和缓存都已清理；限制单次进程保留代次数，到达上限提示重启应用后继续开发。

### 7.3 表现更新

1. 校验新包、入口、依赖和 SDK 兼容性。
2. 在正常帧边界暂停本机 UI 提交，记录可选的光标、焦点等表现状态。
3. 创建新版表现实例，提供当前会话服务及最新可见快照。
4. 可检测的初始化检查通过后切换界面，断开旧信号并释放旧节点，再恢复输入。
5. 失败保留旧界面并报告阶段、错误和旧/新构建 ID。

应提供 `capture_view_state / restore_view_state` 可选接口，减少热更新后焦点、选格丢失。

规则指纹与表现指纹需要拆分：规则代码、操作 Schema、规则配置数据及共享依赖进入规则指纹；纯 UI/资源进入表现指纹。旧协议要求整个包指纹一致，因此“单端更新表现仍保持对局”的能力需要新的兼容协商，不能悄悄绕过旧校验。

### 7.4 规则更新

只由房主发起，且所有参与者必须声明支持同一升级流程：

```text
准备候选包
→ 房主建立操作屏障并记录权威检查点
→ 各端下载、校验、预加载并报告 ready
→ 房主迁移并验证完整状态，或明确选择重开
→ 提交新规则代次及版本，向各玩家发送新可见快照
→ 各端确认后恢复动作
```

状态迁移建议使用 `migrate_state(old_state, old_schema)` 与 `validate_state(candidate)`，仅在房主执行完整状态迁移；私有状态不能因升级发送给其他玩家。旧规则、检查点和动作去重记录在提交完成前保留。

建立屏障前已确认的动作保留结果；旧代次迟到或未确认的动作拒绝，禁止在新规则下自动重放。更新过程另有 transition ID、超时和恢复状态，避免把迁移后的棋盘误当作原对局下一帧。

任一设备未就绪或离线，提交前撤销升级。提交后的恢复需要按升级事务记录使各端重新收敛，不能让某台设备自行回退到旧规则。第一版可将复杂故障处理降级为保持暂停、提示重开。

GDScript 运行错误、死循环或原生崩溃不能承诺都可在进程内回滚。包结构、编译与契约检查先完成；风险较高的候选在开发机独立进程预检，移动端下次启动可回到上一个已验证构建。

## 8. 实现阶段与验收

### D1：结构化观察与正常操作

- Debug / Release 隔离、令牌认证、设备信息、当前会话快照及订阅。
- Session 操作结果和幂等关联；最小 `nvctl` 与机器可读契约。
- 验收：AI 连接电视，读自己的可见状态并完成整局；每手得到最终结果；断开订阅再连可恢复；Release 无开发监听。

### D2：界面与资源更新

- 分块上传、校验、构建并存、规则/表现指纹与协议兼容协商。
- 重建表现、恢复焦点、激活和可检测失败回退。
- 验收：对局中改变棋盘配色或布局，不重装 APK，状态和座位保持；坏包不替换正常界面。

### D3：规则更新

- 对局屏障、全端 ready/提交、状态 Schema 与迁移、超时和恢复。
- 验收：两台设备同步升级；迁移失败保留旧局；断线和迟到操作不会制造两套规则状态。

首轮先交付 D1，再做 D2。D3 不作为第一版网络调试的前置条件。

## 9. 验证清单

- 未认证连接和被撤销令牌无法读取状态或提交动作。
- `play` 模式的房主连接也不泄露其他玩家手牌、牌堆、恢复凭据或 Debug 令牌。
- 相同 request_id 重试只执行一次；过期版本、旧对局及旧代次操作被拒绝。
- 慢订阅者与大日志不会阻塞对局；事件积压有上限并可重同步。
- 中断上传、坏哈希、非法路径及超限包无法激活。
- 更新后旧 UI 信号不重复提交，新 UI 能恢复遥控器焦点。
- 多端版本不一致、升级中断和迁移失败有明确可观察结果。
- 检查真实 Release 产物和运行行为，确保不携带或暴露开发服务。
