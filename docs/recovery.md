# 联机健康检查与恢复（0.1.5）

游戏通道支持可协商的 `heartbeat_v1`。每台设备仍是完整客户端，没有中心服务器。心跳属于 Session 通信能力，Mod 无需实现或处理。

## 健康检查

协议 2 的参与者在 hello 中声明 `capabilities: ["heartbeat_v1"]`，房主支持时在 welcome 中返回同一能力；双方完成该协商后，才为这个连接启用心跳。旧客户端或旧房主不声明能力时保持原通信方式。协议 1 不启用心跳。

每端每 2 秒最多发起一个挑战，使用 8 字节随机数的 16 位十六进制 nonce：

```json
{"type":"ping","nonce":"4d15b2f9a742a310"}
{"type":"pong","nonce":"4d15b2f9a742a310"}
```

对端收到 ping 原样回复 pong。只有匹配自己尚未完成挑战的 pong 才更新健康时间，普通消息、他人的 ping 和无关 pong 不续期。持续 8 秒没有成功确认就关闭运输连接；心跳不经过 Mod，不改变规则版本，不进入操作回执缓存。每连接只保留一个尚未确认的 nonce，避免缓慢回复被后续挑战覆盖。

参与者在 TCP 已连接但 10 秒内未收到 welcome 时关闭连接，防止一直卡在握手。Debug 快照的 `connection_error` 为 `heartbeat_timeout`、`handshake_timeout` 或运输层明确断开时的 `transport_lost`。单向丢包时可能由任意一端先判定心跳超时，另一端随后收到 TCP 断开，因此错误码可能是后者。

2 秒与 8 秒是当前原型的固定参数。计时基于本地单调时钟，不依赖设备间时钟同步；实际检测时间受最后一次确认、线程调度和设备挂起影响。

## 恢复边界

- 房主保留房间、座位、规则状态和操作去重记录。心跳断开只更新玩家在线状态，不增加规则版本。
- 普通客户端仍可点击“重连”；常驻控制器自动调用 `room.reconnect`。自动重连能力在控制器中，普通应用本身不会自动尝试。
- 参与者重连创建新的本地 Session，使用原玩家身份和内存凭据重新绑定原座位，获取自己的过滤快照。对局 ID 和代次保持不变，本地 Session ID 与房间代次会变化。
- 未确认的操作始终保留原请求 ID、预期版本和有效载荷。重连后先查回执，未知则原样提交，由房主去重后返回原结果。控制器按 2、4、8 秒退避等待（默认 receipt timeout 为 2 秒），避免在健康超时之前耗尽重试；新本地 Session 获得新的三次发送预算，原动作不变。
- 自动恢复仅覆盖参与者运输连接。房主退出、应用进程被系统回收、恢复凭据丢失、网络切换到新地址后重新发现房间等尚未实现。无传输加密。
- 本次测试是在本机 TCP 代理保留连接、定向丢弃数据，并非真实关 Wi-Fi、飞行模式或 iOS 后台挂起。iPhone 结果来自模拟器，真实设备仍需回归。

## 复现与证据

```sh
python3 tests/recovery_integration.py
python3 tools/build_ios_simulator.py --device <UDID> --install --launch
python3 tests/recovery_integration.py --ios-device <UDID>
```

第二项模拟器测试会离开现有测试房间。测试包括：

1. 健康空闲连接跨越 9 秒仍保持同一本地 Session。
2. TCP 明确关闭、双向静默丢包、只丢下行、只丢上行；恢复后同局、同座位、同棋盘和版本。
3. 房主已经接受一手落子，代理丢掉回执并保持链路静默；控制器自动重连，原请求重复提交，房主仅接受一次，无需手动 resume。
4. 协议 1 客户端空闲超过心跳期限仍能提交；伪造 pong 不会保活；无 welcome 的握手超时。

安全诊断产物为 `build/validation/recovery.json` 和 `build/validation/ios-recovery.json`，不包含认证配置、恢复凭据或私有手牌。

本次还在更新模拟器之前，让新客户端加入已安装的 0.1.4 iOS 房主，空闲 10 秒后继续落子，验证未协商心跳的旧房主兼容路径。Android 0.1.5 基础包已生成；电视仍保留原安装，不通过 Mod 热更新替换平台 SDK。
