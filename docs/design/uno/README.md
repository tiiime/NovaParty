# UNO UI 规范 v0.1 · 玩具牌桌

状态：**基础布局已接入 Mod 并热更新到电视**。本轮包含木桌、围桌头像、牌面、手机手牌、条件操作和菜单；SVG 中更细的图标、转场和自定义弹窗仍作为后续目标。本规范只定义 UNO 游戏内部界面，独立于“星星大作战”的蓝天星星大厅。玩法、隐私和联网逻辑沿用 [UNO 规则](../../uno.md)。

方向：**暖木桌边、砖红绒布、圆润动物头像、彩色大符号牌面**。像朋友围着一张桌子玩牌，减少表单与控件。参考用户提供的 Animal Party UNO 截图中的围桌关系、卡牌层级和当前玩家标记；这里使用原创二维矢量图形，不复制原图角色、PAWS 标志或三维场景。

## 1. 视觉规则

| 元素 | 规范 |
| --- | --- |
| 场景 | 二维椭圆桌面，木边加一层投影；红绒渐变轻微，不做复杂三维房间 |
| 卡牌 | 固定 2∶3、大圆角、奶油白边框、斜椭圆、中央大数字/符号；不再写“黄色 · Y”等牌面说明 |
| 功能牌 | 跳过为禁行环，反转为双向转折箭头，+2 / +4 用大数值；万用牌用四色图形 |
| 颜色识别 | 红/黄/绿/蓝之外，角落增加圆/菱形/三角/波纹；黄色中央字用深棕，不能黄底白字 |
| 牌背 | 统一暖黄 + 原创爪印；对手永远只有牌背和准确数量，不按牌色分类展示 |
| 玩家 | 简单圆润动物头像、昵称、手牌数；重名或默认昵称时显示短代号；可以截断昵称，但不能裁掉区分玩家的代号 |
| 当前玩家 | 头像亮环 + 指向桌面的一个小三角；其他头像不发光，不给所有座位加高亮框 |
| 杂项 | 不显示金币、礼物、商城、聊天流、性能指标；不放三枚常驻“规则/设置/退出”大按钮 |

动物是头像贴纸，不要求制作角色模型、服饰或复杂动作。卡牌和桌面以形状与轻阴影建立厚度，不能把每一块内容都包进白色面板。

## 2. 电视公共牌桌

画布参考 1920×1080，左右安全区 96、上下 54。桌面约占宽度 70%、高度 66%。

- 中心只放**摸牌堆、当前弃牌**。金色双箭头嵌在桌面，表示出牌方向；万用牌后的当前颜色用一个小色标补充。
- 2–6 位实际玩家沿桌边按顺时针稳定排布，位置模板见 tokens。公共屏幕自己不占玩家席位，不展示“我的手牌 0 张”。人数改变只发生于等待页，不在对局中重排。
- 每人头像旁最多画 3 张示意牌背，数量徽章显示真实张数；不把十几张牌背全部展开。
- 当前回合提示贴近当前玩家。罚牌或跳过反馈贴近受影响玩家，不能整屏飞提示，也不遮挡弃牌。
- 左上只留游戏名、局数和公共牌桌标记；右上一个菜单。电视无出牌、摸牌、UNO、抓漏喊按钮。

等待页沿用同一张桌子，真实已加入玩家占位；空位弱化显示“等朋友”。二维码只在允许加入时显示，保留静区；至少 230px，旁边只放“扫码加入”和玩家人数。满员或开局后收起二维码。唯一主操作是“开始这一局”，2 位实际玩家即可开始；人数不把电视算进去。

手机发起者可以在等待页切换“我也参与”；角色设置不进入对局常驻区域。

## 3. 手机与桌面玩家界面

手机参考 390×844，横向边距至少 16dp，底部叠加系统安全区。对手压缩为顶部小弧线，桌面与弃牌放中间，自己的手牌占底部约 65%–94% 高度。

- 手牌最多 9 张时用浅扇形；再多则横向滑动，不继续缩牌。牌宽至少 72dp，至少露出 28dp 牌角，必须看见数字或功能符号。
- 选中牌抬起 22dp、放大约 1.06、使用深色外边与奶油白内边，始终绘制在其他手牌之上；邻牌让位，不能遮住相邻牌的数字角标。
- 可出牌保持饱和；不可出牌轻微压暗，数字仍可读。选中、可出、不可出不能只靠同一种光圈表达。
- 点牌选择，立即抬升并显示“再点出牌”；再点同一张提交。鼠标规则相同。方向键选牌、确认键出牌，焦点移动时自动滚入可见区域。首版不要求拖拽。
- 摸牌直接点桌面牌堆，轮到自己时才显示“摸 1 张 / 摸 N 张”短标签；已经摸到可出牌时同位置变为“保留这张”。不另铺一排摸牌/不出按钮。
- UNO 按钮位于手牌上方右侧的固定位置，只在剩两张或自己的补喊窗口出现；不挤压扇形手牌。两张时点击表示“这次出牌同时喊 UNO”，用已准备状态反馈，随出牌一并提交。
- 万用牌提交前弹出四块大色块，配色名与形状，黄/绿色块使用深色字；不使用下拉框。选色期间收起其他行动提示，保留牌桌作弱化背景。
- 抓漏喊是短暂的次级入口，只在权威状态允许时出现；电视只显示漏喊信息，不可代玩家抓牌。

桌面宽屏保留围桌布局，将自己的扇形手牌放底边；不改成带侧边栏的管理界面。

## 4. 提示、反馈与结算

| 状态 | 表现 |
| --- | --- |
| 等待别人 | 玩家标记 + “小狐出牌”；自己的手牌可浏览，不误显示可提交状态 |
| 轮到自己 | 一条奶油白短气泡“轮到你了”，配自己的回合标记 |
| 叠加罚牌 | 一条明确的“累计罚牌 +8”，牌堆操作同步变为“摸 8 张”；只高亮规则允许的叠罚牌 |
| 最近动作 | 轻气泡约 1.6 秒后消失；同一时刻只突出一个主要任务 |
| 断线 | 持续“玩家断线 · 已暂停”，关闭游戏输入；自己的连接丢失时仅在平台允许的情况下提供“重连” |
| 提交失败 | 牌回原位/保持选中，留下可读提示直到下一次操作或有效状态变化；不能一帧闪过 |
| 结算 | 小面板：动物头像、胜者、本局得分。玩家只有“再来一局 / 退出”两项主操作；关闭面板可回看牌桌 |
| 重赛准备 | 已同意者显示“已准备 3/6”。电视显示大家的准备进度，不提供代替玩家同意的按钮 |

操作反馈立即发生；只有收到权威确认后才把牌飞到桌面。动画约 180–220ms，不能阻塞接下来的输入和快照。减少动态时去掉飞牌、旋转与脉冲，保留静态选中边框、数量变化和回合标记。静音后仍能完整理解结果。

菜单中只放“玩法规则 / 设置 / 退出游戏”；退出继续走宿主确认流程。不能把“已断线”直接写成“正在重连”，也不能用装饰动画冒充网络进度。

## 5. 实现边界与验收

1. 电视不创建私有手牌节点，`view_for` 仍必须返回空 `hand`；美术重设计不改变隐私边界或玩法。
2. 实现优先用 Godot Control/自绘卡牌与矢量资源，不引入三维角色、摄像机控制或重资产依赖。
3. 所有文案保留中英文目录，昵称与短代号保留原值；英文长度不能使按钮挤出安全区。
4. 覆盖 2/3/6 人、7/15/30 张手牌、+2/+4 叠罚、万用牌选色、漏喊、断线、结算和重赛状态。
5. 检查手机触控、鼠标、方向键、连续确认、防重复提交和焦点滚动；实际电视检查远距离字号与边缘可读性。
